# Image manifest

Every file under `docs/images/` is listed here with where it came from. The hygiene check
(`node test/onyx/run-hygiene.mts --only image-manifest`, part of CI) fails when a file is
missing from this table or a row names a file that does not exist.

- **Re-capture status (D6, 2026-11-24).** Four images were re-captured from the packaged build with the real
  pinned 7B model: `onyx-workbench.png`, `onyx-onboarding.png`, `onyx-model-library.png` and the new
  `onyx-agent-attempt.png` (`docs/progress/captures.json`). The inline-edit and commit-message captures were
  attempted and not taken: the 7B model produced no applicable inline proposal within 120 s, and the
  commit-message capture did not find the message in time. Every other `dev` image below is from August
  2026, before the alpha's approval contract and review changes, and **still needs the owner's re-capture**
  on the release candidate; the README says so under each one it still shows. The 15-second demo GIF also
  needs the owner: an automated recording of the 7B model is 95 seconds of a failed edit.
- **Source** is `packaged` (captured from a built `.app`) or `dev` (Code OSS launched from
  sources, or generated by a script on the development machine). No packaged build existed
  when these were captured, so every current asset is `dev`. D6 owns recapture from the
  release candidate and the release-quality asset check; A6 only records what exists.
- **Model** names the local model visible in the asset. `unknown` means the capture did not
  record it; `n/a` means no model was involved.
- **Date** is the date of the commit that last changed the file (`git log -1 --date=short`).
