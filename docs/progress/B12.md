## Decisions made inside the item

- **A cut-off reply fails the run.** It does not complete, and it is not retried automatically: the user
  sees what streamed, is told it was cut off, and can send the request again. Retrying silently would hide
  a runtime that is misbehaving.
- **Nothing from a cut-off reply is applied, even when it parses.** A tool call whose arguments arrived
  whole on a stream that then ended without a finish signal is dropped. The runtime did not say it was
  finished, so it is not treated as finished.
- **Deadlines: ten minutes to the first byte, three minutes between bytes.** A cold model is loaded and a
  long prompt is evaluated before the first byte, and that can be slow on a small machine; a false stall
  there would make a working setup unusable. They are constants. If they prove wrong for real hardware they
  should become a setting, and the datasheet (L5) measures first-token time.
- **Two clocks.** The request is made in the shared process, which enforces the deadlines. The window keeps
  its own, fifteen seconds longer, so that a shared process that cannot report does not leave a run waiting.
- **Validation is strict and coerces nothing.** `timeoutSeconds: "30"` is refused with the reason, where the
  terminal tool used to ignore it and run with the default. Small models write numbers as strings fairly
  often; this turns a silently altered call into a visible refusal the model can correct. It may cost a
  turn. L5 measures how often.
- **`I-03/no-time-budget` stays in the baseline, owned by B10.** Its script is a run the user paused and
  never resumed, which is Module 3's. The stalled-stream way into the class is closed; its mutant shows the
  campaign would see it come back.
- **`I-03/status-overwritten` (B10) has a new reproducing script.** The old one was a silent stream stopped
  by the rig's watchdog; that run now ends at the product's deadline, so the script no longer led to a
  Stop. The new one stops a streaming reply, which is the defect as Codex N5 describes it. The class is
  still seen in the random campaign.
- **The rig's watchdog went from ten to fifteen minutes** of virtual time, because it must be longer than
  the longest the product itself waits. It is reported before any other I-03 finding.

## Limits, stated

- **A reset connection is an error, not `truncated`.** The transport failed; the message is the runtime's.
  Both end the run as failed.
- **`finish_reason: length` is `complete`.** The runtime finished; the output cap cut the text. A tool call
  cut that way has arguments that do not parse or do not validate, and is refused. B13 owns the cap.
- **The reconcile trusts modification time and size.** A file rewritten with the same size inside the same
  timestamp is not noticed until the watcher reports it or the index is rebuilt.
- **The index still reads at most 5,000 files.** B12 makes the index say so; C7 is about what it covers.
- **The process-side deadline has no simulation mutant**, for the same reason as B5's process-side kill: the
  rig replaces the runtime. Its regression is `OnyxStreamTermination`, which was seen red. The window-side
  deadline has a mutant.
