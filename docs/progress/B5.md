## Decisions made inside the item

- **A flooding command is not killed for flooding.** The plan says to stop accumulating, not to stop the
  command. Output past the caps is counted and discarded; the command runs to its timeout or its end.
- **The start and the end are kept, not the first 200,000 characters.** A failing build says what went wrong
  at the end. Before this item the result was the first 200,000 characters and the end was lost.
- **`cwd` goes through the read tools' gate.** One place turns a model's path into a location
  (`IOnyxWorkspaceAccessService.resolve`), so the terminal's working directory gets the same refusals:
  absolute paths, `..`, and a symbolic link that leaves the workspace. A refused directory is refused before
  the approval prompt, so nobody is asked to approve a command that could not run where it said.
- **The setting is a user setting.** `onyx.terminal.passEnvironment` has application scope, so a
  repository's `.vscode/settings.json` cannot turn it on. When it is on, the approval prompt says that the
  whole environment is passed.
- **Withheld variables are counted to the model only when the command failed.** That is when the fact is
  useful, and it keeps the line out of every other result. Names are returned by the runner and not shown.
- **Window close is the window's job, the rest is the runtime's.** The runtime service lives in the shared
  process, which serves every window and is not told when one closes. The window's terminal service joins
  the workbench's shutdown and kills what it started; the runtime kills everything on dispose and on
  process exit.

## Limits, stated

- **A window that crashes announces nothing.** Its commands are ended by their timeouts (ten minutes at
  most), not by the crash. Tying commands to the window's connection in the shared process would close this;
  it needs a change to an upstream file (`sharedProcessMain.ts`) and is not in this item.
- **A process that leaves its group is not killed.** `setsid` or a daemonizing program escapes a group
  kill. SECURITY.md says so.
- **The name rule over-withholds and under-withholds.** `KEYBOARD_LAYOUT` is withheld; a credential called
  `GH_PAT` is not. It is defense in depth and is documented as that.
- **Two defects fixed here have no simulation mutant**, because the rig replaces the process boundary: the
  unbounded stream of output events and the missing kill on `dispose()` in the runtime service. Their
  regressions are the two `OnyxCommandExecution` tests, which run real processes and were seen red. The
  window-side halves of both (retention, and a command outliving its window) do have mutants.
- **On Windows the user is asked before being told it cannot run.** The refusal comes from the runner, after
  approval. Windows is not a supported platform in the alpha (DEC-02).
