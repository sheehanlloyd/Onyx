## What the plan asked for besides the streaming

- **"Before adopting per-tool `anyOf` schemas, probe the supported runtime's accepted subset and record
  it."** They were not adopted. The envelope schema is the one that shipped: four properties, an `enum` for
  the action and for the tool name, a free-form `arguments` object. Nothing new is asked of the runtime, so
  there was nothing to probe for this item. What the pinned runtime actually enforces of a schema (`enum`,
  nested objects) is one of the datasheet's probes (L5), which is where it is recorded.
- **"Re-measure any published constrained-validity claim."** The README says the constrained turn reaches
  100% valid tool use on five of six models and 83% on the sixth. This item changes what is shown while a
  constrained turn streams. It does not change the schema, the request or how a finished envelope is parsed,
  so the claim's subject is untouched. It was not re-measured here: four of the six models are not
  installed. L5 measures the two that are.
- **Argument validation** is B12's and is unaffected by whether C6 ships.

## Decisions made inside the item

- **The answer waits for its action.** If a model writes `answer` before `action`, nothing is shown until
  the action is known to be `answer`. Showing an answer that turns out to belong to a tool turn would put
  text on screen that the turn then contradicts.
- **A tool action shows nothing while it streams.** Its arguments are not prose.
- **Constrained episodes are simulated at the runtime.** A runtime enforcing the schema leaves the model
  nothing to write but the envelope, so the simulated runtime renders each scripted turn as one. The
  personas are unchanged.

## Limits, stated

- **Only the envelope's own `answer` key is followed.** A model that nests its answer somewhere else gets
  the old behaviour: shown when the turn ends.
- **Markdown arrives in pieces.** A code fence inside the answer renders as it completes, as it does for an
  unconstrained reply.
