## The task set of this repository

`docs/research/results/2026-11-22-task-set/tasks.json`: 120 commits authored between 2025-01-29 and 2026-11-20, every one later than 2024-09-25, the latest day one of the three installed models was published. 54 are from 2025 and 66 from 2026; 92 TypeScript files, 23 style sheets, 5 others; the file is at most 12,000 characters before the change. 19 are commits that also changed exactly one test file. None is from a user's requests: that source needs a workspace's opt-in and a journal with accepted proposals, and this set was built from history alone. The eight commits of L9's engine campaign are excluded, because they were used to look at how the models behave (below).

`describe-task-set.mts` checked all 120 against the repository: each commit is there and each hash is the hash of the file at that commit.

## What the instruction is, and the pilots behind it

L9's engine campaign asked "In the file X, make this change: <commit subject>". The 7B model answered three of four agent tasks in prose, and the 1.5B model read the file and said the change was made. A task's instruction is now the commit's message without its trailers, and an agent run is told to read the file and propose the change with the edit tool.

Two pilots were run on the eight excluded commits to see whether that is enough, and they are not committed as results: they are design evidence, recorded here and in Amendment 1.

| Pilot | Units | What happened |
|---|---|---|
| The new instruction, the shipping configuration | 16 | Both models read the file in every run. One run called the edit tool (1.5B, arguments that did not match its schema). No edit was staged |
| Three values of the tool-call protocol | 48 | `constrained-envelope` (what the product derives for both models): 7B 0 edit calls in 8 runs, 1.5B 1. `native`: none recognised, either model. `repaired-text`: 7B 4 edit calls and 2 edits staged, mean score 0.11; 1.5B 11 calls, 5 reached staging, none placed |

No run in either pilot reproduced the author's change. Two things follow, both written into Amendment 1 before any hypothesis campaign: H-2's protocol component keeps all three values, with the product's own value as the primary contrast and `repaired-text` as a secondary one; and a floor of zero successes is named in advance as inconclusive, not as "the components are worth the same".

The second pilot ended with the launcher's exit code 4, "the repository changed during the campaign". It had: this item's files were being edited in the same working tree while the pilot read tasks from it. The comparison cannot tell whose change it was. A campaign that runs while the repository is worked in now reads from a bare local clone (`git clone --local --bare`, `--repo`); the launcher takes one.

## Tier 2 on this repository

The mechanism is in and tested: the probe passes on the reference machine, and `OnyxOracle` runs a verification script that tries the network and an out-of-tree write, sees both refused, and still gets a fail-to-pass verdict. **No task of this repository's set was scored by execution.** The 19 commits with a test change are unit tests of this repository, which need its dependencies installed and its sources compiled inside the worktree; a campaign's worktree has neither, and the sandbox denies the network an install would need. Every score this module reports for this repository is tier 1.

## Scope notes

- **The consent dialog** is described and gated here (`oracleGate`, `oracleConsentLines`); the command that shows it is L11's.
- **Publication days.** Read from the pages on 2026-11-22. The Qwen announcement names the 1.5B and 7B coder models and is dated 2024-09-19, without saying that the weights were released that day; the catalog uses that day, and this repository's set starts at 2025-01-01, months later than any candidate day. The 14B and 32B sizes have no day in the catalog.
- **"After" means the day after, anywhere.** A commit authored on the publication day, or within 14 hours after its end in UTC, is not held out.
- **The product's repository benchmark** now asks for models before it selects tasks, scans 500 commits for 12 tasks (it scanned 200 for 6), and needs 10 scored tasks to rank.
- **The network guard** sees the launcher's own process. It does not see the application of a tier A campaign; the product's outbound connections are D8's egress audit (R-60).
- **`oracleRun`** refuses a folder that is not a linked worktree. Whether the user agreed is the caller's to establish; the runtime service does not show dialogs.
