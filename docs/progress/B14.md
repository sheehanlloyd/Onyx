## What was checked against the runtime's own definition

Ollama's API types (public source, read during this item) define `remote_model` and `remote_host` on the
model-list entry and on the show response, described there as the upstream model name and the URL of the
upstream host. Those are the two fields Onyx reads. The same file defines `context_length` on a running
model (`/api/ps`); that belongs to B13's server-configured number and is taken up in L5, where a live
runtime is available to check it against.

Not checked against a live runtime in this item: LM Studio's `/api/v0/models` and the `owned_by` values of
llama.cpp and vLLM. They are implemented as those servers are understood to answer. A server that answers
differently is shown as unidentified and, under the default, not used: the failure direction is refusal.

## Decisions made inside the item

- **The usable list is the list.** `getKnownModels()` returns only models that are used. Every chooser in
  the product draws from it (routing, autocomplete, benchmarks, review, the tournament); changing its
  meaning is what guarantees that none of them, and no later one, can pick a refused model. Display of
  refused models goes through a separate method.
- **Refused models stay in the picker.** A cloud-backed model that silently vanished would be a puzzle;
  one that is listed as "cloud-backed · not used" with the reason in its tooltip, and that explains itself
  when chosen, is not.
- **Configured endpoints are still probed for their models.** Without that they could not be shown or
  labelled. The probe is a model-list request and carries no prompt. Nothing else is sent until the
  setting allows it, not even a warm-up.
- **LAN is its own switch in both modes.** Turning strict-local off does not turn LAN on.
- **A `cloud` name suffix counts as a report.** Ollama names its cloud models that way; reading it errs
  towards refusing.
- **The model is no longer told that inference is local.** The system prompt said so. It was not something
  the harness knows, and it is gone from the prompt, which changes the prompt's first line.

## Limits, stated

- **Everything rests on self-report.** A runtime that forwards requests and says nothing, or a proxy in
  front of a runtime that passes its answers through, is indistinguishable from a local runtime. The
  README, SECURITY.md and the settings text say this in those words.
- **"Local" for a LAN endpoint means local to that server.** The labels say where requests are sent and
  that the server reports running the model; they do not say the model runs on this machine.
- **Error messages elsewhere still say "the local runtime"** when a request fails. They describe a failure,
  not a location, and are left for the documentation pass in Module 5.
- **The README hero image and charts are unchanged.**
