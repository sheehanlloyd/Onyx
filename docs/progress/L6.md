## Decisions made inside the item

- **Grounded means sent by something other than the model.** A line in the model's own earlier reply is not
  evidence that the line is in the file. This is what makes the evicted case visible: the read result is
  gone, the model's words about it are not.
- **Whitespace-insensitive, line by line.** A numbered read prints `12| \treturn a;`; the model may quote
  it with or without the number. A line is "shown" when it is in a message with surrounding white space
  ignored. Short lines are therefore nearly always shown; the signal is in the distinctive ones.
- **Keyed by the tool call's id.** A certificate names the call and which edit of the call. The next turn's
  prompt carries that call with its arguments, which is how the anchor is recomputed offline. For that the
  journal's snapshot of a tool call now includes the call's id.
- **Two ways to catch a changed certificate.** The seal catches a careless change. A change that is sealed
  again is caught by recomputing from the prompt. Neither is cryptography: the digest is the trace's
  32-bit one. It is a consistency check for a researcher, not a defence against a forger.
- **The base digest and the match count are not recomputed.** They need the file as it was, and a journal
  does not hold it. The check says so; the match count of a staged edit is one by B6.
- **Grounding never blocks.** As the plan says. The ungrounded edit in the test is staged.

## Limits

- **A journal keeps a prompt up to a fixed size.** Beyond it the offline check answers "not recomputable".
- **Nothing is measured on a real model yet.** How often small models edit from memory is L14's question.
- **Refactors and inline edits have no anchor**, so their certificates say only what kind of proposal it is.
- **One unit run of this item took four minutes and one unrelated test timed out** (`OnyxCommandExecution
  R-18`, which spawns real processes; load average 12). It passed alone in 3 seconds and in the next whole
  run (337 passing in 23 seconds).

## Two end-to-end runs before the passing one

- **The first failed on L6's own check, and was right to.** The journal held both certificates and the view
  showed no line: a hunk was tied to its edit by the lines of the quote, and the mock quotes from the middle
  of a line. The tie now uses the whole lines an edit touched, with a service test for a mid-line quote.
- **The second aborted before any check**, and not because of L6. The first-run dialog came up after both of
  the moments the runner waits for it at, and, being modal, took a click meant for another dialog. The
  machine was loaded. The runner now looks for that dialog before every prompt and command. This is the
  second abort of the runner today (C8.md has the first, which is still unexplained and may be the same
  thing seen later in a run).
