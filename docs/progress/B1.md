## Decisions made inside the item

- **A request by name.** The plan allows "an explicit playbook request" to replace a spare slot. The rule
  implemented is the same rule for every optional tool, because `remember` would otherwise be unreachable
  on the supported eight-slot profile: the user's message contains the tool's own word ("playbook",
  "remember", "docs" or "documentation") or the name of a repository playbook. It is literal and
  documented in `docs/SUPPORT.md`; nothing is inferred.
- **Below six slots.** A profile that cannot hold the six essentials gets the read tools in the order
  `readFile`, `grep`, `findFiles`, `listDirectory` and no tool that writes or executes. The seed profile for
  models under 4B parameters has three slots, so those models now run read-only where they used to get
  `repoSymbols`, `remember` and `editFile`.
- **Ask mode.** The chat stack does not tell an agent which mode a request came from, so every Onyx run is
  treated as edit-capable, as before. Not changed here.
- **`grep` with `include`.** The glob is handed to the search as an include, which is how the Search view's
  "files to include" behaves: it reaches a file that an ignore file names, though not a file inside an
  ignored directory. `findFiles` and `listDirectory` match their pattern against the search's results
  instead, so they never do. Measured against ripgrep directly before choosing; stated in SUPPORT.md.
