## Decisions made inside the item

- **One result a file, for its latest staging or acceptance.** A new proposal for a file that has a result
  replaces it with "not applied".
- **Partial is a qualifier, not a state.** After one hunk of several is accepted the result is about the
  file as it then is, and its line ends by saying how many hunks are still staged and not part of it.
- **The check task waits for a save and never causes one.** Before C2 the task ran when a tool-using run
  ended, on a disk that held none of the run's edits. Now it runs only on an accepted file that is saved,
  and B2's approval is asked at that moment.
- **`verificationFeedback` (L4) now governs only the "not applied" line at the end of a run.** Verification
  after an acceptance is not a harness choice.

## Limits

- **Clean before and clean after ends as "timed out".** The marker service raises no event when a language
  service reports the same set again, so silence and "nothing changed" cannot be told apart. The service
  never says "verified" without a fresh report. This is the common case for a good edit in a clean file,
  and it reads worse than it is; fixing it needs a signal from the language service that it has looked at
  this version of the file, which the marker service does not carry.
- **Only the accepted file's diagnostics are compared.** Problems the change causes elsewhere are left to
  the project check.
- **Results are not kept across a reload.**
- **No simulation of a language service.** The rig's marker service is real, but nothing reports to it in
  generated episodes; the swap, moved, timed-out and stale cases are driven by the unit tests.
