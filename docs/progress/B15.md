## The mechanism, and why

Measured against Ollama 0.33.0 (`mechanisms.json`): the OpenAI-style endpoint ignores a context sent with a
request in either form, and a model loaded with a larger context through the native endpoint is reloaded at
the server's allocation by the next OpenAI-style request. Three ways work: the native endpoint's per-request
option, a server setting, and a derived model.

**Chosen: the derived model**, with consent. It is the only one of the three that changes nothing about how
Onyx talks to the runtime and nothing about the user's server. The native endpoint would be less visible on
the runtime, and was not chosen: it is a second wire protocol for tool calls, schemas and stream endings,
none of which L5 measured, and every other request on the OpenAI-style endpoint would throw the model back
to 4,096. The server setting is the user's.

The alias shares the weights: its manifest names the same model layer, and adds a 17-byte parameters layer
(read from the runtime's manifests during the probe: the model blob `sha256:29d8c98fa6b0…` in both; disk use
of the models directory 7,508,388 KiB with the alias and 7,508,376 KiB after its removal).

## Decisions made inside the item

- **Default 16,384, not the trained 32,768.** "Default conservatively." It costs 0.8 GiB for the 7B model
  and 0.4 GiB for the 1.5B, and no speed. The setting raises it.
- **96 KiB a token for the memory ceiling.** First set at 64 KiB from a quick reading; the committed
  measurement gave 69 KiB for the 7B model, so the constant was raised before the final run.
- **Verified is the reported number, never the size of a prompt.** The probe confirms recall at about nine
  tenths of it and loss a quarter past it. The first version of the probe stopped at three quarters in
  estimated tokens, which the runtime counted as 64% of the allocation; that was too weak a basis for the
  word, so the deciding prompts are now sized in the runtime's own tokens.
- **An allocation that is not verified is discarded.** The alias is removed and the record says why.
- **A verified allocation replaces the server's number and a datasheet's context**, which both describe the
  model's own name. An overflow learned before the allocation is forgotten; one learned after it narrows it.
- **Datasheet format 2.** Stored format-1 datasheets are not read; the model is measured again.
- **The manifest field is required**, and the one manifest already committed was amended with what that run
  had measured (the server reported 4,096; nothing requested, nothing verified).

## Where this departs from the plan's wording

- **"Ollama and LM Studio."** Only Ollama was probed. LM Studio is installed on the reference machine and was
  not running; starting it was outside what the session was authorised to do. Onyx asks LM Studio for
  nothing and budgets against the loaded context it reports. Step 1 is unfinished for LM Studio.
- **"Both pinned models run at the chosen context."** They did, for the measurement, and the aliases were
  removed afterwards so that the owner's runtime is as it was found. In the product the alias exists only
  after the user agrees.
- **No end-to-end check.** R-61 is "service, node" in the catalogue. The mock runtime does not implement
  `/api/create`; the two commands were not driven through the window.

## For the owner

- **Nothing changes until the command is run.** A fresh install still budgets against the server's 4,096.
  Whether onboarding should offer the request outright, rather than mention it, is a product choice.
- **A model not yet loaded has no server number**, and is budgeted at its architectural context until the
  next discovery after its first request (B13's known gap; unchanged here).

## Found while doing this

- Sending a prompt past the allocation makes Ollama keep about half the context (8,194 tokens counted of a
  16,384 allocation; 2,050 of 4,096), not all of it.
- First-token time from cold is dominated by whether the weights are in the file cache; the cold numbers in
  the table differ by context for that reason and should not be read as a cost of the larger context.
