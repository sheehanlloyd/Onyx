## Decisions made inside the item

- **A segment, not a substring.** `..` is traversal only as a whole path segment. Segments made only of dots
  and spaces with two or more dots are refused with it; a single `.` is the current directory, as before.
- **Twice.** The real location is checked at staging, so the model is told at once, and again before the
  write, because a proposal can wait for a long time and the file system can change under it.
- **For a new file, the nearest existing directory decides.** A file that does not exist has no real
  location. The read side treats that as "inside", which is right for a read (there is nothing to read) and
  wrong for a write.
- **The refusal message keeps its wording** ("the path contains "..", which could leave the workspace"), so
  no trace of a refused traversal changed.

## Limits

- **The in-memory disk of the tests does not redirect a write through a link.** It answers `realpath` as a
  linked disk would, which is what the product asks, so the refusals are tested; "nothing was written
  outside" in the tests follows from the refusal, not from an attempted write that was contained.
- **Windows is not covered**: drive letters and UNC paths are refused as absolute or for their backslash,
  and junctions, short names and trailing dots have not been tried. D-module work.
- **Not checked between the last check and the write.** The second check narrows the window; it does not
  close it. Closing it needs a file-system primitive the file service does not offer.
