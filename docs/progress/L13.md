## H-2: inconclusive, because nothing succeeded

*For models at or below 7B, tool-call protocol handling contributes more to task success than any other harness component, and the gap narrows with model size.*

The design is Amendment 1's: a full factorial over three components (tool-call protocol handling with three values, tool-result elision, read-tool line numbering), 12 configurations, both pinned models, 40 held-out tasks of this repository, one seed at temperature 0, through the agent loop. 960 runs.

**No run reproduced the author's change: 0 of 960.** Every configuration's success rate is 0 of 40 (Wilson interval 0 to 8.8%) for both models. Every Shapley value, main effect and interaction of task success is therefore exactly zero. The registered thresholds make that inconclusive, and the analysis says why in its own words: a floor is not evidence that the components are worth the same.

What the runs did, by tool-call protocol (160 runs a model and protocol):

| Model | native | repaired-text | constrained-envelope (the product's) |
|---|---|---|---|
| qwen2.5-coder:7b: runs that proposed an edit scoring above 0 | 0 | 12 | 0 |
| qwen2.5-coder:1.5b: the same | 0 | 1 | 0 |

- **Under native tool calls** neither model calls a tool at all: the run ends after one turn of prose. That agrees with the datasheets (0 of 5 requests on the tool channel).
- **Under the constrained envelope**, which is what the product derives for these models, the models call the read tool and then answer. No run of 320 proposed an edit that scored above zero.
- **Under repaired text** the 7B model proposes edits: one that scored above zero in 12 of 160 runs. None was the author's change.

The secondary measure, mean score, decides nothing by registration. It is reported because it is not at the floor in one game: for the 7B model, moving from native to repaired text is worth 0.019 of mean score (0.003 to 0.041), and no other component's interval excludes zero.

**What this says about the product**, which is more than the hypothesis asked: on 40 real single-file changes from this repository, the agent loop with either pinned model under the product's own configuration completed none and attempted an edit in none. The two models are the ones the catalog recommends for a 16 GB Mac.

## H-7: inconclusive, because nothing succeeded

*Model rankings differ between repositories often enough to change which model a user should pick.*

Two repositories, as Amendment 2 said in advance: this one, and Homebrew/brew from the history already on the machine (35 Ruby and 5 shell tasks). Three models, 40 held-out tasks each, one request a task at temperature 0.

| Repository | qwen2.5-coder:7b | llama3.2:3b | qwen2.5-coder:1.5b |
|---|---|---|---|
| this repository: tasks solved; mean score | 0 of 40; 0.040 | 0 of 40; 0.037 | 0 of 40; 0.017 |
| Homebrew/brew: tasks solved; mean score | 0 of 40; 0.146 | 0 of 40; 0.069 | 0 of 40; 0.021 |

No model solved a task in either repository, so neither has a ranking by the registered metric, and the outcome is inconclusive. Amendment 2 named this case before the campaign ran. By mean score, which is not the registered metric, the order is the same in both repositories.

## Red before green

- `h7-rankings.test.mts` failed on its first run: one expected value of Kendall's tau was mine and wrong (−1/3 for a pair of rankings whose tau is 1/3). The decision code was not changed.

## Scope notes

- **Written before a defect in the campaign engine was known.** The agent-loop campaign of this item ran with it: for up to a minute after each checkout, a prompt's background named up to five recently committed files of the previous task. `docs/progress/L15.md` has what it was, how it was found and fixed, and why this campaign was not run again (PREREGISTRATION.md, Amendment 4).
- **Two of five components.** Eviction and verification feedback are left out of the factorial, for the reasons in Amendment 1: at a context of 16,384 tokens with an eight-turn cap eviction does not happen, and verification feedback acts only after an edit is accepted, which a campaign never does.
- **One seed.** At temperature 0 a second seed is a second copy.
- **Machine condition.** Other applications were open and several gigabytes of swap were in use. The load average is in each `campaign.json`. Nothing here is a throughput claim.
- **A finding outside the hypothesis:** in the numbered-read configurations the 7B model sometimes quotes the read tool's line numbers inside its SEARCH text, and the edit is refused. Counting it is L14's subject (H-3).
- **Homebrew/brew** was read from a bare local clone of the copy already installed. Nothing was downloaded, and nothing of Homebrew was changed.
