## The new run, and what it could not cover

Run at commit 0eebedd1d8b with a clean tree, against a private Ollama 0.33.0 on a loopback port, stopped
afterwards. Three models: `qwen2.5-coder:7b`, `qwen2.5-coder:1.5b`, `llama3.2:3b`.

| | 7B | 1.5B | llama3.2:3b |
|---|---|---|---|
| Native tool channel | 0/6 | 0/6 | 6/6 |
| Usable after Onyx's repair | 6/6 | 6/6 | 6/6 |
| Schema-constrained | 6/6 | 5/6 | 6/6 |
| Repository benchmark, mean score | 0.08 (5 tasks) | 0 (5) | 0.03 (4; one timed out) |
| Attempts that removed a line the author kept | 4 | 2 | 2 |

- **The machine was busy, and the throughput numbers are low for it.** The one-minute load average was 39
  when the run began and 14 when it ended, on 14 cores: Spotlight and the file-provider daemon, working
  through what the builds of this session had written. The run waited 25 minutes for the load to fall and it
  rose instead. The 7B model measured 21.6 tok/s; the same morning, idle, it measured 49 (B15). The report
  records the load, and the README says so beside the numbers. A quiet re-run is worth doing; it is not
  done.
- **LM Studio was not measured.** It was not running, and this session does not start the owner's
  applications. The LM Studio rows of the tool-calling result and the whole speculative-decoding result are
  from August 2026 and their raw reports were never kept. They stay in the README as prose, marked as earlier
  measurements without a raw report, and their chart (`chart-speculative.svg`) is withdrawn. The README's
  opening box still summarises the August result across both runtimes; it is the owner's text and links to
  the section that now says which half was re-measured.
- **Eight of fourteen attempts removed a line the author kept.** That is the defect the audit described,
  seen in real replies: under the old metric none of them would have been penalised for it.

## Decisions made inside the item

- **The cap is 0.5, by judgement.** The plan says "caps the score" and gives no number. Precision alone
  prices one lost line among ten good ones at 0.95. The cap makes any loss of the author's code worth at
  most what a wrong edit of the right line gets.
- **"Capped" is said only when the cap lowered the score.** A reply that scored 0 and also removed kept
  lines says both, without the word.
- **Old routing scores are dropped, not converted.** They were taken under a metric that could not see
  deletions; there is nothing to convert them with.
- **The provenance block is in the report itself**, not only in the manifest L3 already required: a report
  that travels alone still says where it came from.
