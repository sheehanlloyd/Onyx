## Diagnosis of the red `main` runs (A7.1)

The last two runs on `main` (482d0d1d2ae and 56a2ba98515, 2026-09-02) failed at **Type check** with
`Cannot find module 'electron'` across `src/`. The run before them (273bb1aab6f, 2026-08-30) was green.

| Path | What happened | Evidence |
|---|---|---|
| Cold (no cache) | `npm ci` runs; `build/npm/postinstall.ts` calls `ensureElectronTypes()`, which downloads `electron.d.ts` to `.build/typings/electron.d.ts`; `src/tsconfig.base.json` maps `electron` to that file; typecheck passes; the job saves `node_modules`, `build/node_modules`, `extensions/*/node_modules`, `remote/node_modules`, `remote/web/node_modules` | 273bb1aab6f: "Cache not found … Run npm ci … Cache saved" |
| Warm (cache hit) | The cache restores only `node_modules` directories. `npm ci` is skipped, so postinstall never runs and `.build/typings/electron.d.ts` does not exist. `tsc` resolves `electron` to a missing file | 56a2ba98515 and 482d0d1d2ae: "Cache hit for: onyx-node-modules-Linux-580fb98a…" then `TS2307: Cannot find module 'electron'` |
| Fresh checkout | A new clone with `npm ci` type-checks and compiles (the isolated checkout: `npm run compile` finished with 0 errors) | this session, 2026-11-19 16:53 EST |

The plan names the artifact as `node_modules/electron/electron.d.ts`. In this tree electron is not an npm
dependency; the types live at `.build/typings/electron.d.ts`, outside every cached path, and nothing in the
restore path regenerates them. Upstream's own `.github/workflows/pr.yml` runs `node build/npm/electronTypes.ts`
as a separate step after its cache for exactly this reason.

A second defect showed up in the first run of this branch (cold cache, 2026-11-19): `npm ci` failed because
`@vscode/ripgrep`'s postinstall downloads the prebuilt binary through the GitHub releases API, which answered
`403` to an anonymous request. Upstream passes `GITHUB_TOKEN` to `npm ci`; this workflow did not.

Fix, in two commits so the warm failure is reproduced on this branch rather than assumed:

1. Part 1 (this commit): `GITHUB_TOKEN` on the install step, the inventory step, the e2e on push, the asserting
   benchmarks, the fresh-output protocol and the self-checks. The cold run should be green and save a cache.
   Re-running the same commit against that cache reproduces the warm failure, with the inventory step showing
   `MISSING .build/typings/electron.d.ts`.
2. Part 2: a "Regenerate what the cache does not hold" step after the cache: `npm ci` when
   `node_modules/.postinstall-state` or any `node_modules` directory that `build/npm/dirs.ts` installs is
   absent, and `node build/npm/electronTypes.ts` always (it verifies the checksum and downloads only when the
   file is missing or wrong); the cache paths now cover every dirs.ts directory under a v2 key. Two
   consecutive green runs follow, the second a cache hit.
