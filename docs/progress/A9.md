## DEC-05 recommendation

**Keep the current base through Module 1's gate; rebase onto 1.147.0 at the start of Module 2, after HUMAN
confirms.** The trial shows the rebase is low-risk in source (no API breaks, five predicted conflicts, Onyx tests
green on the merged tree) and bounded in infrastructure (one toolchain migration: pnpm 12 + Node 24.22.1, CI and
docs). Doing it before B1 means the read-side tools, the packaged release mode and the signed candidate are all
built once, on the runtime the alpha will ship. Retaining the August base to the candidate would ship Electron
42.8.1; if HUMAN chooses that, the maintenance/risk decision must say so and schedule the rebase before D2.
Elapsed time alone never makes either choice releasable (DEC-05): the rebased tree must pass the activated
gates again, which the weekly drill and Module 1's gate command make a one-afternoon check.
