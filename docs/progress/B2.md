## Decisions made inside the item

- **The check task asks too.** `OnyxTaskVerification` ran a `tasks.json` task after every tool-using run
  when `.onyx/config.json` named one: repository content causing execution with no approval, by a route
  that never touched the terminal tool. It now asks before each run with the same two choices. The dialog
  cannot show what a task runs and says so. C2 (Module 3) still owns what verification means; this only
  closes the authority gap.
- **Clearing legacy grants edits a tracked file, on request.** The only place earlier versions stored a
  grant was `terminalAllowlist` in `.onyx/config.json`. `Onyx: Clear Legacy Terminal Grants` removes that
  key after a confirmation and leaves the rest of the file alone. Nothing writes approval state to a
  tracked file any more.
- **Recommendations are not shown in the approval dialog.** A line saying "the repository recommends this
  command" next to the Run Once button would be repository text arguing for its own approval. The list
  appears only in `Onyx: Show Effective Project Configuration`, labelled repository-authored.
- **Two tests were replaced, not weakened.** `onyxTerminalPolicy.test.ts` asserted the contract this item
  removes (an allowlisted command runs silently; a safe command offers session and always). Their
  replacements assert the opposite at the same layer.
