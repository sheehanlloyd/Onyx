## Decisions made inside the item

- **Names are exported.** Tool names, model ids, runtime names, statuses and digests are kept as they are,
  when they have the shape of a name. Without them a redacted bundle diagnoses nothing. SUPPORT.md lists the
  fields. A model a user named after a client is in the bundle under that name; SECURITY.md says so.
- **Log messages are content.** A log line can interpolate anything, so the default bundle keeps each
  line's timestamp and level and the length of its message. That is much less than a log, and it is what
  can be promised. The opt-in brings the messages back.
- **One opt-in, relabelled.** The checkbox now names what it includes: prompt text, file contents, command
  text and output, paths and log messages.
- **Free-text settings are named, not exported.** `onyx.verification.task` and `onyx.autocomplete.model`
  are strings the user typed; the bundle lists them under `setButNotExported`. Enumerated strings, booleans
  and numbers are exported.
- **The final scrub is belt and braces.** Every entry's text, however it was built, has the stored API key
  values, URL credentials and bearer tokens removed last. If a future entry is added carelessly, a key
  value still cannot be in it.
- **The settings migration is automatic and silent in the UI.** It is logged. A notification on every
  start until the user acts would be worse than moving a secret out of a plain file; SECURITY.md and the
  setting's deprecation message say what happens.

## Limits, stated

- **The allowlist knows today's records.** A new journal event kind is left out of bundles until it is added
  here. That is the intended failure direction, and it will cost a debugging session some day.
- **A secret with the shape of a name, in a name field, is exported.** If a tool were called by an API key,
  it would be in the bundle. The scrub removes the keys Onyx stores; it cannot know other secrets.
- **Keys in memory.** The model service holds each endpoint's key in memory while Onyx runs, as before.
- **The key still travels in settings sync if the user had synced it earlier.** This item removes it from
  the local setting; it does not reach into a sync service's history.
- **`onyx.speculative.pairs`** is an object keyed by model names; it is not walked and is listed as not
  exported.
