## The measurement

Both pinned models on a private Ollama 0.33.0, load average 3 to 4, one edit of one line at seven
enumeration sizes, three trials each, the prompt identical at every size. The first token is not delayed
by the grammar at any size (24 to 35 ms on the 7B model, 9 to 19 ms on the 1.5B). The whole reply slows as
the list grows: 0.97 s at 50 lines, 1.15 s at 400, 1.82 s at 1,600 on the 7B. All 36 constrained edits named
anchors that were on the list and were the line asked for. One task, the easiest there is.

The private runtime was started for this and stopped afterwards. Nothing was pulled, created or removed.

## Decisions made inside the item

- **A third action of the envelope, not a second tool.** The plan asks for an alternative `editFile` shape
  for constrained turns. The envelope's `arguments` is a free object, so the shape that can be enumerated
  has to be in the envelope's own schema: `{"action":"edit","edit":{…}}`, which the loop reads as a call of
  the edit tool. It uses `enum` inside a nested object and nothing else, which is what L5 measures.
- **Measured enforcement, not assumed.** The protocol is available only when the datasheet measured that
  the runtime enforces a schema. A runtime that is merely assumed to does not qualify.
- **The harness does not rely on the runtime.** The tests run against a runtime that enforces nothing. An
  anchor that is not on the turn's list is stopped by the argument check every call passes (B12), and the
  rest by `resolveAnchorEdit`.
- **Numbered where shown twice.** Following the plan: a line by its text unless it was shown more than once
  in its file, then by its number. A line shown once and present elsewhere in the file, unseen, resolves to
  "duplicated" and is refused with the numbers.
- **Free-form search and replace stays available** in the same turn. An arm that removed it could not
  create a file or edit one it had not read. The certificate says which protocol each edit used.
- **An anchored edit is refused for a file that already has staged changes.** Its anchors are lines of the
  file as read, and what is staged is not in the file.
- **The enumeration is not counted against the context.** It is a constraint on decoding, not prompt text.

## Not done here

- **No simulation mutant and no generated episodes.** The rig's scenario and mutant tables run under the
  default configuration, and this protocol exists only under a lab one. The five service tests are the
  coverage. A mutant that skips the check against the turn's list would be the one to add when the tables
  can carry a configuration.
- **Not tried end to end in the app**, and not on LM Studio.
- **Whether it helps is unknown.** The plan says so, and nothing here changes that.
